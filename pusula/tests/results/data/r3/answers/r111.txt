# Plan: Electron to Tauri (notes-desk 1.4.0)

Status: draft

## Goal
The app runs on Tauri v2 with the same behavior. That means auto-saving notes, markdown preview, an "Open file" picker for txt and md, and signed auto-update. Electron code and dependencies are gone.

## Out of scope
- New features or a UI redesign.
- A frontend bundler.
- The Tauri 3 alpha.
- Signing certificates and store publishing.

## What I found in the code
- `main.js` has 3 IPC handlers: `notes:read`, `notes:save`, `file:pick`. It also has a 900x600 window, `autoUpdater` and a quit rule.
- `preload.js` exposes these as `window.api`.
- `index.html` loads `marked@12.0.2` from a CDN. `renderer.js` puts the output into `innerHTML` without cleaning it.
- `package.json` has no `build` key. So there is no appId, no update feed, no targets and no icons.
- There are no tests and no lockfile.

## Decisions
| Decision | Reason |
|---|---|
| Tauri v2 stable (core 2.12.x) | The alpha is not used unless you ask. |
| Keep the old API names and a `window.api` shim | `renderer.js` stays unchanged. |
| File picker runs in Rust | The webview gets no file-system permission. |
| One capability for window `main`, strict CSP | The window label is the security boundary. |
| Errors return `Result<_, String>` and are shown in the UI | No silent errors (AGENTS.md). |
| Window size, file filter and file name go to config | No hardcoded values (AGENTS.md). |

## Risks
1. Old notes are lost, because the data folder name changes. Prevention: Q1 and a migration test.
2. Losing the updater private key ends all updates. Prevention: back it up before the first release.
3. Installed Electron apps cannot update themselves into Tauri. Prevention: users reinstall once, and the last Electron release stays online.
4. Capability mistakes show only at run time. Prevention: step 10 calls every command.
5. CSP may block the app. Prevention: check the console in step 7.
6. Unsanitized markdown can run page script that calls commands. Prevention: strict CSP, minimal capability, Q3.
7. OS webviews differ. Prevention: test each shipped OS. This machine is Linux only.
8. There is no packaging config today. Prevention: Q2, and I won't claim packaging is done for untested targets.
9. Linux libraries may be missing. Prevention: step 3 comes first.
10. The dialog plugin docs may differ from this plan. Prevention: step 1, and stop and report on conflict.
